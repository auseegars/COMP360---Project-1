Ayana Seegars and Jevaun Keith  
COMP 360-01, Programming Languages, Fall 2026

This program reads one input file, prints each lexeme with its token type and line number, and checks whether the input follows the LearnCompiler grammar. It reports the first syntax error prominently, then continues checking and displays additional diagnostics. Missing tokens can cause follow-on diagnostics, so fix the first error before interpreting later ones.

## Build and run

Open this folder in CLion and build the Project1 target. Set the program argument to `sample1.txt` and the working directory to this project folder. Repeat with `sample2.txt`. If no argument is supplied, the program prompts for the file name; paths containing spaces are supported.

You can also compile with a C++20 compiler:

```text
g++ -std=c++20 -Wall -Wextra -Wpedantic project1.cpp -o Project1.exe
Project1.exe sample1.txt
Project1.exe sample2.txt
```

## How it works

The lexer skips whitespace and keeps track of line numbers. It recognizes `float`, lowercase identifiers, and the grammar's punctuation and operators. Names containing numbers, uppercase letters, or underscores are marked invalid. For example, `test2` is reported as one invalid lexeme.

The parser has a function for each main grammar rule: `program`, `declares`, `assign`, and `expr`. It requires at least one declaration, followed by one assignment. Expressions contain identifiers separated by multiplication or division operators. After the closing brace, it checks that no extra tokens remain.

The assignment's sample ends its assignment with a semicolon, but the written assignment rule does not include one. The parser accepts either version so the provided valid sample passes. It identifies the first error and uses token insertion and statement boundaries to recover and continue checking. Repeated declarations and expression operators use loops within the recursive-descent functions to avoid excessive call-stack growth. It checks syntax only; it does not evaluate expressions or check whether names have been declared.

## Sample results

`sample1.txt` is accepted and prints:

```text
The Sample Program is generated by the BNF grammar
```

`sample2.txt` is rejected at `test2` on line 1 because identifiers can contain only lowercase letters. The missing declaration would be a later error, and the parser reports that error after the invalid name.

A successful run returns 0. Invalid input or an unreadable file returns 1. Full output from both supplied samples is saved in `sample1-output.txt` and `sample2-output.txt`.
